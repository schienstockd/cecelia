# Julia API (`api/src/`)

- **Image geometry (Julia, metadata only)**: `api/src/image_geometry.jl` — `open_level(zarr_path, level_idx=0)` (the array at a chosen pyramid level + NGFF axes, handling BOTH on-disk layouts — the tile route asks for a coarser level, the timecourse asks for level 0), `open_level0` (sugar for the L0 case every caller before the tile route used), **`read_native` (read pixels through this, NEVER `arr[idx...]` — bioformats2raw stores are big-endian `>u2` and Zarr.jl hands back the bytes UNSWAPPED with a native eltype, so a raw `default` version silently reads as byte-swapped garbage and renders as saturated white noise)**, `read_ngff_axes`, `axis_dims` (Zarr.jl is column-major, so C-order axis i sits at Julia dim `ndims-i+1` — never map positionally), `resolve_image_version` (a versioned `filepath` → path; `nothing` ⇒ ACTIVE), `image_geometry`, `GET /api/images/geometry`, and `GET /api/images/stores` (`store_compression` + `_path_bytes` per version/label set — what the image-metadata modal shows against each stored file; the size is a directory WALK, so it is answered on demand for one image and never folded into the `/api/images` listing). **The frame extent is per-VERSION, not per-image** — drift correction expands the canvas and a crop shrinks it — so ask this rather than storing a size on the image. Was private to the old `crop_render.jl` (`_crop_*`) until a second consumer showed none of it was crop-specific.

- **server.jl**: single `HTTP.listen` entry; `handle_stream` (WS upgrade + static serving), `handle_http` route table, `broadcast_ws` fan-out, `BroadcastLogger`, chain-event→WS bridge, `handle_ws` loop.
- **Writing a response body**: `write_http_body!` (`app/src/utils.jl`, exported) — THE way to put a materialised body on the stream, from `handle_stream`, static/asset serving and the task runner alike. Never `write(stream, body)`: no route sets `Content-Length`, so HTTP.jl frames responses CHUNKED and frames each `write` as its own chunk — a zero-length write emits the *terminating* `0\r\n\r\n` and `closewrite` emits a second, so the next response on that keep-alive connection is parsed starting at 4 stray bytes (Vite's proxy: `HPE_INVALID_CONSTANT`). One legitimately-empty response — a track-grained gating plot of an untracked segmentation — therefore failed every OTHER request sharing the connection. Enforced by the `response bodies go through write_http_body!` testset (call sites) + `an empty response body is written through write_http_body!` (the wire bytes, in the package suite).
- **sockets.jl**: `handle_message` (the one inbound-WS switch), task telemetry `ws_log`/`ws_status`/`ws_result`/`ws_progress`, `handle_task_run`/`handle_chain_run`/`handle_movie_batch`.
- **runner_api.jl**: the API server's half of the detached task runner — launch/adopt it (`_ensure_runner!`), relay its frames into the existing `ws_*` sinks, reconcile after a reconnect; `/api/runner/status|restart|enabled`. The runner itself: `app/src/runner/`.
- **routes.jl**: project/set/image + chain-template CRUD, task-definition serving, fs browser, `api_images_tasklog` (reads the task log file), lab-log routes.
- **movie_helpers.jl**: the shared movie / legend / view helpers (`_compare_grid`, `_wrap_grid`, `_grid_frame_total`, `_t_sweep_frames`, `_movie_out_path`, `_movie_named_path`, `_config_value_names`, `_config_compare_segmentations`, `overlay_legend_content`, etc.). Consumed by `sockets.jl` (movie recording), `movies_api.jl` (file naming), `viewer_api.jl` (props / pick-rect / overlay-legend) and the offline movie rail.
- **movie_render.jl**: the offline renderer's sweep — `record_view_movie` (2D timelapse: a crop + stride as a head-on camera on a z slab) and `record_keyframes_view_movie` (2D and 3D keyframes, the view state's raw camera + its canvas height) both hand states to `writers/render_animation_run.py`, the viewer's own shader; **stills** on the same params — `render_view_stills` (a 2D view's frames as PNGs: card filmstrips via `behaviour_cards.jl`) and `render_view_state_still` (one view state, 2D or 3D: keyframe thumbnails), rendered by the resident preview worker's `render` when it is up, else one-off (`STILLS_VIA`, `docs/todo/STILLS_WORKER_PLAN.md`); `movie_overlay_style` (point / tail / border / opacity / z tolerances), `_mask_params!`, `interpolate_keyframes`, `viewstate_to_render_args`/`crop_from_view_state`/`z_from_view_state`, timestamp + scale-bar overlay specs.
- **shader_constants.jl**: the defaults the viewer, its shaders and the movie renderer share, read from `frontend/src/lib/webgpu/shaders/constants.json` — `OVERLAY_Z_TOL`, `MASK_FILL_OPACITY`. Add a shared default THERE, not as a Julia literal.
- **overlay_author.jl**: resolves pops/tracks once for every movie — `build_overlays3d_for` (per-t positions; the shader projects), `merge_overlay_closures` (several track sources), `mask_id_colours` (which labels a population mask draws, in what colour — the shader's colour table), `movie_mask` → `MovieMask` (`ViewerPalette()` or a table), `pixel_transform` (a 2D view's region + stride), `hex_to_rgb`/`rgb_to_hex`, `OVERLAY_GREY`, `CECELIA_TRACK_PALETTE`/`TRACK_COLOR_MODES` (read from `frontend/src/plots/palettes.json`).
- **movie_config.jl**: `MovieConfig` → `MovieRecordConfig` (viewer/animation) | `MovieBatchConfig` (batch) — what produced a movie, built at the WS boundary and banked into `settings/movies.json` by `register_movie!`.
- **Server-side image preview render (the ONLY one — reuse it, don't hand-roll a second)**: `api/src/image_render.jl` — `composite_rgb` (multichannel → RGB: clip to contrast, colourise, additive blend; pure + unit-tested), `layer_display_specs` (per-channel display settings), `percentile_spec` (auto-contrast), `CMAP_RGB` (**fallback only** — a channel's colour comes from the `colormap_lut` saved into the props JSON; do NOT re-derive the palette here, that duplication is what rendered `bop blue` as white), `render_preview_frame` (z-MIP one timepoint of one image VERSION → PNG bytes), and `cached_render!` (bounded FIFO byte cache). **Need a server-rendered thumbnail/preview? Start here.** Reads the zarr directly (`Zarr.jl`) — a sanctioned narrow carve-out for *previews only*; `zarr_utils` stays canonical for processing. Was `crop_render.jl` until an audit found nothing in it was crop-specific.
- **Gating as pictures**: `api/src/gate_plot_render.jl` — `render_gate_plot` / `render_gate_plot_png` (PURE raster of the Gate page's plot at 2×: panel background, 1.4-px anti-aliased dots in 64 density buckets via `point_densities` (port of `plots/density.ts`) through the shared `_heat_ramp`, square plot area, browser tick formatting (`_fmt_tick_label`), channel-name axis titles (`_axis_title`), gates stroked + named as `GateOverlay` does; text from the glyph atlas `api/assets/plot_font.json`, built by `scripts/build_plot_font.py`). Routes in `api/src/gating_views_api.jl`: `GET /api/gating/plot-image` (builds on `_plot_xy` + `_child_gate_outlines`, the helper plotmeta shares) and `GET /api/gating/cells-image` (one still on `render_view_stills` with a `MovieMask` coloured inside/outside a population). Consumer: the autonomous MCP's `gate_plot` / `gate_cells_view`. **A plot as a PNG for a non-browser client? Start here.**
- **Agent run review (Blackboard)**: `api/src/blackboard_run_review.jl` — an agent run record's `agentRun` marker and per-section verdicts (`sectionOutcomes`, `POST /api/blackboard/section-outcome`; a Claude caller's verdict is a proposal that never replaces a person's). `_BB_PASSTHROUGH_KEYS` carries both fields through every other `_write_bb_meta!` write. AGENT_RUN_REVIEW_PLAN P2.
- **Crop-preview routes** (a MIP + info endpoint reused by the `imagePicker` task-param widget): `api/src/crop_api.jl` — `GET /api/crop/info` + `/api/crop/frame` (cached) and nothing else; the crop-specific part is the route names plus downscaling the reported frame size to `maxPx`. Frontend: `ImagePickerModal.vue` (scrubbable MIP + rectangle draw + z/t range), used by every task whose spec declares an `imagePicker` param — today `editImages.cropImage` on the **Preprocessing** module page. Pure box maths in `frontend/src/utils/crop3d.ts`. See `docs/todo/CROP_PANEL_PLAN.md`.
- **editImages.copyImage** (`app/src/tasks/editImages/copyImage.jl` + `.json`): duplicate ONE image version into a NEW image (fresh uid) in a new/existing set, dropping all derived data — a re-import shortcut. Task-rail (background + progress + universal toast). Zarr copied VERBATIM via `_copy_tree_with_progress` (Julia recursive dir copy, NOT a `zarr_utils` re-encode — preserves layout/levels/OME sidecar); `_copied_meta` carries calibration + `ori_path` + `copy_source_*`. Frontend: the **Copy** button in the Import action bar (`ImageFileActions.vue`) → `CopyDialog.vue` (version + destination-set picker; takes the whole SELECTION and dispatches one task per image). QC-exempt (duplication).
- **Image file operations (copy / move / delete)**: `frontend/src/components/ImageFileActions.vue` — the three standard file actions on the image SELECTION, mounted ONLY in `ImportModule`'s ModuleLayout `#actions` slot (no other module page can delete or re-file an image). Copy → `CopyDialog.vue`; Move → `/api/images/move` per image (manifest-only); Delete → `DeleteImagesDialog.vue`.
- **Image deletion (the ONE per-image surface)**: `frontend/src/components/DeleteImagesDialog.vue` — five scopes over the selection, each mapping to one route: whole images (`/api/images/delete` — a real delete: `delete_image!` `rm -r`s `0/{uid}` AND `1/{uid}`), versions + new-active (`/api/images/version/remove`), label sets (`/api/images/labels/delete`), runs (`/api/images/analysis/runs` lists, `/api/images/analysis/runs/delete` deletes — one track set, HMM run, clustering suffix, graph … via the `RUN_KINDS` registry in `app/src/analysis_runs.jl`), all analysis (`/api/images/analysis/reset`). It only builds a **plan**; `ImageFileActions` executes it, so the loop + `k/N` readout + toast live in one place. Pure rules (intersection across the selection, `default`-last ordering, new-active must survive) are the tested **`frontend/src/utils/imageDelete.ts`** — don't re-derive them in a template. There are exactly **two** deletion surfaces app-wide: this modal (per-image, deliberate) and Settings → Storage (whole-project, automatic); the napari ViewerPanel label delete was removed and the `importImages.remove` task is `hidden` from module pages (still registered + a valid chain node — see `docs/MODULES.md` → *hidden*). Design + decisions: `docs/todo/IMAGE_DELETE_PLAN.md`. Move/Delete are HTTP loops and report themselves (a `k/N` readout + a completion/partial-failure toast); Copy reports through the task rail via **`taskStore.addMany(items, toastLabel)`** — the batch entry point that raises ONE "started" toast for N entries (N × `add()` = N toasts). The "existing set OR new set by name" destination + its collision check is the shared **`frontend/src/utils/setDestination.ts`** (`resolveSetDestination`/`destinationParams`, tested) — used by both Copy and Move, never re-validated inline. These were per-row actions (a ⋯ item each + a delete ✕ at the end of every row) and worked one image at a time. See `docs/UI.md` → *File operations*.
- **gating_api.jl**: population manager + gating engine routes; **owns the shared helpers** (`_gating_image`/`_resolve_vn`/`_gerr`/`_live_map`) reused by tracking/plotting/napari (include-order coupled — `gating_api.jl` first).
- **plotting_api.jl**: summary-canvas routes (thin wrappers over `plot_summary_data`).
- **hmm_state_cards_api.jl**: `POST /api/hmm_state_cards` — one snapshot card per HMM state on a `live.cell.hmm.state.<measure>` column (medoid = the state-run whose track spends most of its life in that state); discovery mirrors `motif_cards_api.jl`, render via `render_medoid_filmstrip`. Frontend: `frontend/src/components/plots/HmmStateCardsView.vue` (thin `CardsPanelInner` wrapper, registered as `hmmStateCards`).
- **tracking_api.jl**: `/api/tracking/motion-dims` preflight.
- **notebooks_api.jl**: Pluto engine lifecycle (:7660) + registry/snapshot CRUD + sysimage build. **The sysimage stamp — freshness AND which recipe built the image — has ONE implementation: `pluto/sysimage_stamp.jl`**, which this file `include`s by path (it is deliberately dependency-free so an env that can't depend on the pluto project can still load it). Don't re-derive `deps.so`/`.stamp` paths, the Manifest fingerprint, or the stamp readers here or anywhere else — that copy existed, was "kept in sync" by hand, and drifted the moment a field was added.
- **app_api.jl**: `_stop_children_for_exit`, `/api/app/shutdown|restart`, dev worktree-switch.
- **storage_api.jl**: `/api/storage/summary` (walked disk/reclaimable scan) + `/api/storage/reclaim` — thin adapters over `storage.jl`.
- **repl_api.jl / update_api.jl / setup_api.jl**: diagnostics + gated REPL; self-update; first-launch wizard.
- **observer_api.jl**: `/api/observer/status` (assistant CLI present + the generated MCP config path) and `/api/observer/register` (one-click register of the observer MCP in the user's Claude config — the only route that touches it).
- **system_api.jl**: `/api/system/envs` (+ `/install`, streamed over WS) — probe/install the opt-in pixi envs in `_OPT_IN_ENVS` (today `cellpose-v3`). Client: `utils/systemEnvs.ts`.
- **plugins_api.jl**: `/api/plugins/install|install-local|remove` — pinned tarball fetch (never git), unpack via `Cecelia.plugin_unpack!`; the listing rides `/api/tasks/custom-modules`.
- **maintenance_api.jl**: `GET /api/maintenance/patches` — lists `maintenance_patches()`; running one is the WS `maintenance:run` action.
- **tls.jl**: `tls_paths`/`ensure_dev_cert` — self-signed cert under `<config_dir>/tls/` via system `openssl`; `nothing` ⇒ the server falls back to HTTP/1.1. The preference: `app/src/config/tls.jl`.
- **preview_api.jl**: `/api/preview/status|start|stop|run` over the resident `preview/preview_worker.py` (:7656); a run whose viewer store ≠ the task's store is a 409, never a silent switch.
- **task_validate_api.jl**: `POST /api/tasks/validate` — form-time param advisory for `backendAdvisor` (`tasks/paramAdvisors.ts`), answered by the Julia validators in `app/src/tasks/param_validators.jl`.
- **correction_plan_api.jl**: `/api/correction-plan/presets|recommend|get|save|mount` over `correction_plan.jl` (`mount` → `plan_to_chain_template`, gated by `overwrite`).
- **labels_api.jl**: `GET /api/labels/ids` — real cell label / track ids for a segmentation (`kind=cells|tracks`), capped at `limit` with `total`/`truncated`, `sample=true` for a stride sample.
- **landscape_api.jl**: `/api/viewer/landscape` (browser publishes, MCP `get_landscape` reads; in-memory, 1 h TTL) + `/api/viewer/landscape/compute` (server-side per-tile channel/seg/pop/track summary with `sourceRun` provenance).
- **vault_api.jl**: the model-vault primitives shared by `denoise_api.jl` + `optical_flow_api.jl` — `safe_vault_model_name`, `vault_model_row`/`vault_model_bytes`/`vault_model_mtime`, `vault_rename`/`vault_delete` (pooled `.pt` and per-channel bundles). `vault_model_stem` stays in `config.jl`.
- **task_console.jl / dev.jl**: standalone `pixi run console` WS *client*; the `pixi run dev` supervisor. (Both outside the server.) Palette: reads `share/console_palette.json` — same CVD-safe swatches the recital console (`python/cecelia/effectiveness/palette.py`) uses, so both dev consoles render as one system.
- **Behaviour cards (cell / motif / HMM state)**: `api/src/behaviour_cards.jl` — `render_medoid_filmstrip` (the ONE card renderer: crop, trace, saved viewer specs, board-asset PNGs) plus the shared sidecar cache discipline every family uses: `cards_specs_mtime` (saved viewer display mtime — contrast/LUT invalidation), `parse_card_seeds` (`seeds: {cardPath: n}`), `read_cards_sidecar`, `cards_stamp_fresh` (serve only on an exact stamp match), `CardMemo` + `card_filmstrip!` (per-card frame reuse on a miss). A new family builds its stamp from these, not a fourth hand-rolled cache check. Handlers: `cell_cards_api.jl`, `motif_cards_api.jl`, `hmm_state_cards_api.jl`.
