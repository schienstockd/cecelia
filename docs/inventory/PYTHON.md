# Python utilities (`python/cecelia/utils/`)

- **measure_utils**: `measure_from_zarr` — per-cell morphology + intensity; writes a NEW `labelProps/{vn}.h5ad`.
- **segmentation_utils**: `SegmentationUtils` base — tiled segmentation loop, seam stitching, post-processing, nuc↔cyto matching, `_write_labels_zarr`. **Swapping the algorithm is one subclass + `predict_slice`** (cellpose today, stardist/coastal later) — the Julia-side counterpart is `app/src/segmentation.jl`, below.
- **cellpose_utils**: `CellposeUtils(SegmentationUtils)` — cellpose **4** (Cellpose-SAM) predict, channel prep, µm→px diameter, auto-GPU. v4 quirks live here and nowhere else: no `channels=`/`model_type=` (both silently ignored upstream), one model zoo (`cpsam_v2`/`cpsam`), and `z_axis` only legal with `do_3D` or `stitch_threshold > 0` — a Z stack with no stitching goes plane-by-plane. `split_z_gaps` repairs cellpose's `stitch3D` reusing ids across an empty plane (one label = one z-contiguous object). `docs/SEGMENTATION.md` → *Cellpose 4*.
- **model_weights**: `download` (atomic, `[PROGRESS]` bytes), `fetch(name)` — built-in cellpose weights into cellpose's own cache. Run by the model-weights job (`run_py`, `--params {"models": [...]}`) and the installers (`python -m cecelia.utils.model_weights cpsam_v2`). `docs/SEGMENTATION.md` → *Model weights*.
- **coastal_utils**: `CoastalUtils(SegmentationUtils)` — optical-flow segmentation. The only TEMPORAL subclass: sets `TEMPORAL_RADIUS` so the base hands `predict_slice` a window of frames, reads its flow-metric set from the model's `<name>.json` manifest, projects the window at the GLOBAL photometric scale, and does per-Z 2D + `match_masks_3d` for 3D. Calls coastal (`flow_metrics_for_frame`, `LearnedAffinityInference`); the cecelia side owns none of the algorithm.
- **tracking_utils**: `BayesianTrackingUtils.track_objects` (btrack) + `write_track_props` (new `{vn}__tracks.h5ad`).
- **(Images × population) grouping for the TRACK PLOTS (Julia)**: `app/src/tracking/track_cohort.jl` — `track_plot_groups` (the ONE resolver turning the board's own selectors — `imageUids` / `groupAttr` / `poolImages` / `popType`+`pops` / `poolPops` / `maxGroups` — into `TrackPlotGroup`s, each holding the cell frames it draws from) plus the two readouts, `track_group_paths` (geometry + per-track colour values, keyed `"{source}:{id}"` when a group pools several) and `track_group_diagnostics` (the celltrackR battery over the group's frames POOLED). `/api/tracking/{paths,diagnostics}` are thin JSON shapers over it — the grouping is data work and `api/src` has no DataFrames. Frames come from `pop_df` when a population is named and `label_props` when none is; the attribute join is `image_attr_groups`, the ref grammar is `_split_pop_ref` — neither is restated here. **Pooling is `pooled_track_frame`** (`tracking/track_diagnostics.jl`): track ids are per IMAGE, so a plain `vcat` merges two cells into one track and invents the step between them; it offsets by a round decimal stride and tags each row's source, which is what `track_diagnostics(…; group_col=)` uses to keep the O(n²) pair scan inside one movie. See `docs/TRACKING.md` → *Both track plots compare like every other plot on the board*.
- **clustering_utils**: shared Leiden engine (`find_populations` + `split_back_and_write`); used by both cluster runners.
- **BLAS thread budget**: `run_py` sets `OPENBLAS_NUM_THREADS` = `BLAS_THREADS_PER_TASK` (`app/src/py_runner.jl`, currently 4) on every Python task it spawns; the preview worker gets the same. A pool limit caps concurrent TASKS, not threads — any BLAS call takes every core, so `cpu` at 20 means 20 × 32 threads. Bounded is the default because uncapped is measurably worse: drift 56.3 s → 31.8 s solo, 309.7 s → 70.7 s ×4; clustering and KDTree flat; dense SVD 2.30 s → 1.28 s. **`OPENBLAS_NUM_THREADS` only, never `OMP_NUM_THREADS`** — that throttles torch, the one workload that does want the cores (0.19 s → 0.34 s). To DEVIATE (outside `run_py`, or a measured need): `cecelia.utils.cpu_utils.limit_blas_threads`. Enforced by the `run_py bounds the BLAS thread pool` testset. See `docs/SCHEDULER.md` → *Thread budgets*.
- **correction_utils**: AF + drift correction (drift shifts, AF channel correct, denoise/rolling-ball/top-hat). **AF is TWO mechanisms in one pass and they are not interchangeable**: `af_bleedthrough_alphas` derives a per-ordered-pair coefficient for what the FILTER SET leaks and `af_correct_frame` subtracts that *amount* first, then applies the dominance weight for what the TISSUE emits into several channels — and the bleedthrough estimator is chosen per combination by `exclusive` ("different cell types"), because whether a voxel can carry both markers is a fact about the experiment that no amount of looking at pixels supplies; it moves the coefficient 5x on real data — and a competitor identified as a leak source is dropped from the weight, because scaling by the same overlap it just subtracted undoes the subtraction (measured: 6.4% vs 83% of co-positive signal retained). **Drift estimation is one function — `estimate_drift`**, returning a `DriftEstimate` (shifts, absolute positions, and the diagnostics QC banks: cycle residual, rejected/interpolated frames). `drift_correction_shifts` is a thin wrapper kept for external callers. Don't hand-roll a `phase_cross_correlation` loop: this one caches each frame's FFT (every frame is both the moving image of one pair and the reference of the next), runs it in float32 on multiple threads — 3.5× measured — and solves the trajectory from overlapping frame pairs so a chain of neighbour measurements can't integrate its own errors. `drift_residuals` is the reliability number (`drift.unreliable`); `drift_frame_slices`/`drift_frame_origins` are where the pixels land (→ `write_valid_box`).
- **smooth_utils**: the smoothing task's per-frame compute — `build_spatial_fn` (gaussian via `coastal.smooth`, or Anscombe-VST bilateral), `estimate_gain` / `estimate_gate_sigma` (seeded whole-image samples), `smooth_timepoint` (spatial-then-temporal, shared-kernel gated / farneback), `apply_gain`. Called by `smooth_run.py` AND the preview worker's `_preview_smooth`, so a preview is the run's arithmetic. Imports coastal lazily.
- **coloc_utils**: pairwise pixel-colocalisation statistics — `tls_slope` (orthogonal regression), `pearson`, `costes_threshold` (Costes et al. 2004, the automatic threshold Imaris/Coloc 2/JACoP implement) and `envelope_slope` (the LOWER envelope of the joint distribution, i.e. the *proportional* part of a pair). The one home for these — a second hand-rolled Pearson or regression over two channels is the bug it exists to prevent. Its caller today is `correction_utils.af_bleedthrough_alphas`, which needs the envelope slope to separate filter-set bleedthrough (proportional, global) from broadband autofluorescence (structure-specific). Pure, takes paired samples; gathering them is the caller's job.
- **norm_cache**: per-image cache for whole-movie normalisation percentiles — `path_for`, `fingerprint`, `key`, `read`, `write`. THE place a `(lo, hi)` pair that needed every pixel of a movie is kept between runs; a `.normstats` sidecar beside the store (not `.json`, so sidecar discovery cannot pick it up). Staleness is by key + store fingerprint, never a warning — a changed setting misses and recomputes; `variant` separates two ways of deriving the same range. Used by flow training and by segmentation's `normaliseToWhole`.
- **intensity_utils**: whole-stack intensity statistics from streamed per-channel histograms — `channel_histograms`, `hist_percentile`, derived background level (`background_threshold`/`triangle_threshold`), `clip_stats`, and clipping-at-acquisition detection (`is_saturated`/`saturation_stats` — STRUCTURAL, a pile-up in the brightest occupied bin, so it works on a 12-bit sensor stored in 16-bit words where a dtype-max test reads 0). Used by AF correction, segmentation normalisation and the import saturation QC.
- **dim_utils**: `DimUtils` — dimension-order/index/physical-size/slice reasoning off an ome-types OME object. Core dependency of most tasks.
- **slice_utils**: numpy slice tuples — multiscale X/Y strides (`create_slices_multiscales`), named-axis crops (`crop_slice_tuple`), task-preview bounds (`preview_region_bounds`). No tiler: segmentation's XY tiles are `SegmentationUtils._create_xy_tiles`.
- **napari_utils**: project-agnostic napari layer builders (`add_image`/`add_labels`/`add_tracks`), hex↔rgba, clip planes, view snapshot, movie recording, colour-by helpers. Imported by the bridge (and coastal). View snapshots come in two grains — whole-viewer `capture_view_state`/`apply_view_state`, and the per-layer `capture_layer_props`/`apply_layer_props` they are built from (what the task preview uses to keep a contrast window across a re-preview, without restoring the camera). Read/write layer display props through these, never attribute-by-attribute.
- **script_utils**: subprocess plumbing — `StdoutLogger` (`[PROGRESS] n/total`), `script_params`, `get_param`.
- **math_helpers**: `round_up`/`round_down` to a multiple.
- **rechunk_zarr**: standalone CLI — rewrites flat stores to per-plane chunks (low-level surgery; reuses `plane_chunks`).
- **centroid_migrate**: `normalise_centroids(adata)` — THE converter from any prior centroid layout (skimage `centroid-0..N`, old-R flat columns) to explicit-obsm `centroid_x/_y/_z` + `centroid_t`; idempotent; the remedy the `label_props_utils` read guard points at.
- **legacy_migrate**: old R/Shiny project → Feijoa (images, segmentation, tracking only) — `scan_project`, `migrate_image`, `migrate_h5ad`, `read_rds` (base-R helper), `read_ome_meta`. Entry points `scan_legacy_run.py`/`migrate_legacy_run.py` (`importImages.migrateLegacy`).
- **mesh_utils**: the spatial MESH route — `build_label_meshes` (marching cubes per label, on the fly, never persisted), `nearest_surface`, `mesh_proximity_edges`, `mesh_aggregates`; used by the `spatialAnalysis` mesh contact/aggregate runners.
- **flow_probe**: numeric check that the optical-flow engine still produces what a model was fitted on — `fingerprint()` (a fixed synthetic window through `coastal.flow.flow_metrics_for_frame`) + `compare(recorded, current)`, `VERSION`. Recorded by `opticalFlow.train`, checked in `coastal_utils`.
- **plane_render**: one COMPUTED 2D plane (flow metric map, probability head) → PNG — `plane_png`, `stretch_to_uint8`, `colormap_lut` (baked viridis/magma LUTs, no matplotlib). Stored images render via `api/src/image_render.jl`; consumer is `preview/preview_worker.py`.

## Python tasks & writers

- **Task runners**: `app/src/tasks/<category>/<name>_run.py` — thin subprocess entry points co-located with their `.jl`/`.json` (segment, cleanupImages, tracking, editImages, importImages, clustPops, clustTracks). Run by path via `run_py`; reusable logic lives in `python/cecelia/utils/`, not the runners. (`python/cecelia/` is the IO library only — no task runners.)
- **Data-layer writers**: `python/cecelia/writers/*_run.py` — e.g. `write_categorical_obs_run` (delegates to `obs_utils`).
- **wgsl_utils**: the viewer's WGSL for the movie side — `expand_wgsl(name, **vars)` / `expand_source`, `shader_constants`, `UniformLayout(name).pack({'cam.dist': …})`. Reads `frontend/src/lib/webgpu/shaders/` (same files the browser compiles); twin of `shaderSource.ts`, both tested against `shaders/golden.json`.
- **wgpu_host**: headless WebGPU (`wgpu-py`) host for the viewer's shaders — `MipHost` (`set_volume`/`set_lut`/`set_palette`/`set_labels`/`set_points`/`set_segments`, `render(w, h, lanes)` → sRGB RGBA; MIP, then tails, then points, as the viewer draws), `request_adapter` (GPU, else software fallback). Uploads only; the drawing is `shaders/mip*.wgsl`. The viewer's CPU-side inputs, golden-pinned to the TS: `view_camera` (≡ `applyViewStateToBrowser`), `lut_rows` (≡ `lutTextureBytes`), `label_palette` (`shaders/label_palette.json`).
- **Movie writers (offline renderer)**: `writers/render_animation_run.py` (every movie — keyframes, viewer Record, batch, compare-grid cells, 2D and 3D — drawn by the viewer's own MIP + overlay shaders on `wgpu_host.MipHost`; 2D = a z slab head-on at the zoom's pyramid level, only the region the frame shows (`_xy_region`); population masks via `wgpu_host.label_table`; any GPU or a software adapter, no CUDA; + timestamp/scale-bar/title card; `render_frames` is the one frame loop, `render_stills` writes them as PNGs — `outPaths` — for card filmstrips and keyframe thumbnails, served warm by the preview worker's `render` command), `writers/stitch_movies_run.py` (compare-grid compose via `movie_io.stitch_movies`).

## AI-assist effectiveness (`python/cecelia/effectiveness/`)

- **effectiveness.log**: `append_event`/`read_events`/`default_log_path` + `EVENT_TYPES`/`OUTCOME_VOCABULARY` — the closed schema for `~/.cecelia-effectiveness/events.jsonl`, the substrate for every reviewer-emission signal. Design: `docs/todo/EFFECTIVENESS_LOG_PLAN.md`; row shape: `docs/ai-assist/EFFECTIVENESS_METHODOLOGY.md`.
- **effectiveness.recital**: `run_recital` — one-command spawn of fanout audit + convention check via `claude -p`, plus the mechanical inventory check and maintainability lint; emits `_run` and `_finding` rows atomically with the spawn (so autonomous-mode skips can't hide). Wired to `pixi run recital`; called by the agent before every commit per root `CLAUDE.md` → *Git & commits*.
- **effectiveness.rollup**: `render_rollup` — reads the jsonl, renders the public `docs/ai-assist/EFFECTIVENESS.md` (per-mechanism counts + finding rows joined to `_finding_resolved` outcomes + ratchets + misses). On-demand via `pixi run audit-rollup`.
- **effectiveness.console**: `format_event`/`render_dashboard`/`DashboardState`/`follow_events`/`main` — live view of the log, the recital-side twin of `api/task_console.jl` (`pixi run console`). TTY: full-screen dashboard with per-mechanism counters, a recent-findings pane (wrapped descriptions; PgUp/PgDn or the wheel scroll, → full text / ← cut) and an activity pane; pipe / `--stream`: append-only formatted event stream. Wired to `pixi run recital-console`. **Scrolling a full-screen terminal view**: `scroll_window` (cut + `↑`/`↓ N more · PgUp/PgDn` rows + clamp) `decode_key`/`poll_key` (PgUp/PgDn and the arrows named, other escapes dropped), `scroll_step` (page or `WHEEL_ROWS`) and `ENTER_ALT_SCREEN`/`LEAVE_ALT_SCREEN` (where the terminal sends the wheel as ↑/↓) — shared with `pixi run judge-review`, don't hand-roll a third. Reuses `log.default_log_path` + `log.read_events`; does NOT share the finding-row formatter with `rollup.py` (markdown vs ANSI are different output media — both read the payload fields the same way).
- **effectiveness.palette**: `load_palette` + named swatch constants (`VERMILLION`/`ORANGE`/`YELLOW`/`BLUISH_GREEN`/`SKY_BLUE`/`BLUE`/`REDDISH_PURPLE`/`GREY`). Reads the Okabe-Ito CVD-safe palette from `share/console_palette.json` — the ONE source both dev consoles use (`effectiveness.console` here + `api/task_console.jl` on the Julia side). Semantic mapping (which swatch is "running", which is "confirmed") stays in each console because the two have disjoint concepts. Palette drift is a load-time error, not a first-paint one.
- **effectiveness.inventory_coverage**: `run_inventory_check` — mechanical check: warns when the staged diff adds a shared file (utils/lib/composables/stores/components, `app/src`, `api/src`, `python/cecelia`, `mcp`) that no `docs/inventory/*.md` names, and every route added to `api/src/server.jl` that `docs/API.md` → *Route index* doesn't list. Fired inside `run_recital`; one `inventory_coverage_run` row per run, carrying the warned `files` + `routes`.
- **effectiveness.maintainability_lint**: `run_maintainability_lint` / `lint_diff` — mechanical check for the `docs/MAINTAINABILITY.md` rules a regex can see: a task file the diff pushes past 200 lines, and incident history (dataset uids, dated authorship, phase codes, commit SHAs) in added comment lines. `MAINT-EXEMPT: <reason>` opt-out. Fired inside `run_recital`; one `maintainability_lint_run` row per run. Plan: `docs/todo/MAINTAINABILITY_ENFORCEMENT_PLAN.md`.
- **effectiveness.git_context**: `current_pr` / `current_branch` / `current_head_sha` / `repo_root` — the one place recital + the commit hook discover git state; `main_checkout` (the checkout every worktree belongs to, from any of them); `merged_prs_since` (the weekly judge's stranded-commit scan) is its merged-PR list. `parse_diff` → `FileDiff` / `DiffLine` — the one line-level unified-diff parser; the mechanical checks build on it, never a raw-text regex. `merged_pr_heads` (a branch's merged PRs with the head each merged at — "is this squash-merged branch's work in main?", used by `scripts/prune_worktrees.py`). `pr_for_branch` — one gh-shell-out helper, cached inside the rollup render pass, so a findings-heavy branch pays for `gh pr list` once, not per finding.
- **effectiveness.claude_cli**: `resolve_claude_bin` — the one way the AI-assist tooling finds the `claude` CLI (`shutil.which`, so the Windows `claude.cmd` shim resolves). Used by recital, the weekly judge and the autonomous runs; each caller decides how a missing CLI fails. Also THE usage-limit reader for every `claude -p` caller: `rate_limit(out)` (a `--output-format json` result or a stream-json `result` event → the CLI's message on a 429 / limit refusal), `RateLimited`, `reset_at` (when it lifts, in the CLI's zone), `rate_limit_note` (`{message, resetAt}` for a run record), `limit_exit` (one stderr line + `EX_TEMPFAIL` = 75 for a CLI tool), `failure_text`. The judge re-exports them as `judge.X`; don't hand-roll a second 429 check.
- **effectiveness.state**: `state_dir` (the folder beside the effectiveness log) / `try_lock(path)` (exclusive non-blocking lock as an open file, `None` when held; POSIX only) — the one state folder + one-at-a-time lock for the weekly judge (`scripts/judge/weekly.py`) and guide runs (`scripts/agent_eval/guide_run.py`).
- **effectiveness.judge_staleness**: `judge_record_warning` — the recital console's one-line warning when the weekly judge's newest run record (`judge-runs/` beside the log) is older than cadence + slack, or failed, or (`backlog_warning`) its backlog grew two passes in a row. `backlog` is the one count of a pass's candidates waiting for the judge. Warn-only.
- **effectiveness.agent_sandbox**: `SANDBOX_SETTINGS`, `make_detached_worktree` / `remove_worktree`, `parse_stream_json` — the one containment + checkout + stream reader for every sandboxed `claude -p` agent (the judge's verify agents, the autonomous runs). `StreamSignals.rate_limited` = the run ended on the usage limit.
