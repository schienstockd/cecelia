# Napari bridge (`napari/`)

- **preview_worker.py** (`preview/`, :7656): the task-preview worker — a resident process that runs a task's REAL compute (`CellposeUtils.predict_slice`, not a second implementation) over the one region napari is showing, so params can be judged before committing to a full run. Resident because a process that can segment costs 17.7 s of imports; on the un-pooled `jobs.jl` rail, because a preview that queued behind a segmentation isn't a preview. Returns the mask block (never writes a store). Julia half: `app/src/preview.jl` (`PreviewWorker`, `preview_request`, `preview_show_command`, `show_task_preview!`/`hide_task_preview!`); API: `api/src/preview_api.jl` (`/api/preview/{status,start,stop,run}`); viewer: `napari_bridge.show_task_preview` + the `viewChanged` listener; frontend: `stores/taskPreview.ts` over `utils/taskPreview.ts` + `utils/debouncedLatest.ts`. Previewability is a declared task trait (`task_previewable`, `app/src/tasks/task.jl`), stamped onto each spec by the definitions route. `pixi run preview` / `stop-preview`. See `docs/SEGMENTATION.md` → *Previewing params BEFORE a run* and `docs/todo/TASK_PREVIEW_PLAN.md`.
- **Coalescing a burst — THREE helpers, one per kind of work** (frontend). A slider/drag/ResizeObserver fires far faster than the work behind it; never hand-roll a fourth `setTimeout` + sequence-token pair. Rule + which to pick: `docs/UI.md` → *Continuous controls*.
  - **A request** → `utils/debouncedLatest.ts` — one run per burst, never two in flight, `isCurrent()` so a superseded reply can be discarded. Consumers: `stores/taskPreview.ts`, `composables/useFlowPlanes.ts`, `components/canvas/SummaryPanel.vue`, `components/CropPanel.vue`, `tasks/ParamRenderer.vue` (the param advisory), and the live napari pushes below.
  - **A paint** → `utils/rafCoalesce.ts` — one apply per animation frame; `peek()` exposes the pending value so steps within a frame compound. Consumers: `components/plots/PlotChart.vue`, `composables/useCanvasZoom.ts`.
  - **A write** → `utils/debouncedSave.ts` — write-behind autosave, plus `duringRestore()`, which suppresses the echo of a restore for a window DERIVED from the debounce (the coupling three stores were each writing down as a hand-picked constant). Consumers: `stores/canvasPanels.ts`, `stores/analysisLayout.ts`, `stores/animation.ts`.
- **Live napari view-property pushes** (frontend): `utils/napariOverlays.ts` → `pushZView` / `pushLabelContour` — the two settings a SLIDER drives on the running viewer, each owning one module-level `debouncedLatest` so a drag lands one command instead of sixty (the bridge runs one command at a time). One scheduler per endpoint, module-level on purpose: a second call site cannot reintroduce the spam. `applyViewState` is the one-shot sibling (keyframe select / zoom-to-source) and is deliberately NOT coalesced. Nobody else may POST `/api/napari/{set-z-view,apply-view-state}` — pinned by `utils/continuousControls.test.ts`.
- **Continuous-control scanner** (frontend): `frontend/src/utils/continuousControls.ts` + its test — parses every `<input type="range">` out of the SFC templates and classifies what its `@input` does (write / emit / call). The test fails when a slider handler *calls* something without naming where the effect lands, and pins the live napari endpoints to one owner. The rule it enforces is `docs/UI.md` → *Continuous controls*.
- **napari_bridge.py**: the whole bridge process — `NapariState` (viewer + per-image state + all command handlers), `execute_command` dispatcher, WS server (`ws_server`, :7655, `_port_available` guard), Qt/asyncio glue. Imports `cecelia.utils.napari_utils`/`zarr_utils` (+ lazy `ome_xml_utils`, `label_props_utils`). No private store readers (consolidated in PR #170).
- **One label-layer adder**: `NapariState._show_label_stores` — the single implementation behind `show_labels`, `show_branch_labels` AND the live preview (`preview=True` → `({vn}) Labels (live)`, level 0 only, cache off; `refresh_labels` re-reads it in place). They differ only in store subdir, layer-name suffix and an `after_add` hook. `_LABEL_SUFFIXES` maps each subdir to every suffix its stores can occupy so adding one evicts its siblings. **Add a label family by calling this, not by copying it** — it had already drifted into two near-copies. See `docs/NAPARI.md` → *Labels*.
- **A napari layer request must name the image ON SCREEN**: `_viewer_shows` (`api/src/napari_api.jl`) guards `show-tracks` / `show-populations` / `colour-labels` / `start-selection`. Each resolves a `CciaImage` from the request while the BRIDGE resolves paths against whatever the viewer holds; nothing checked they matched, so a track panel on one image asked for a segmentation another does not have and the bridge died inside HDF5. The error was the lucky case — two images that both had that segmentation would have drawn one's tracks over the other's pixels, silently. Refuses naming both uids, before any bridge work. Clients should not need it: the track timeline opens the right image first via `useNapariOpen` (never force-launching). Pinned by `api/test/runtests.jl` → *"a viewer showing another image refuses the layer"*.
