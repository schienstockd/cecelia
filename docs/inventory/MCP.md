# MCP observer (`mcp/`)

- **cecelia_mcp/server.py**: FastMCP stdio server `cecelia-observer` — 31 read tools + `mark_tracks` / `mark_cells` / `point_at_ui` / `mark_freeform` (bidir point-out — EPHEMERAL, 5-min-default TTL; `docs/todo/BIDIR_CONTEXT_PLAN.md` PR #4 / #5; incl. `get_recent_logs` = backend console, `get_recent_captures`/`get_capture` = the "look at this" surface (BIDIR share-in, PR #3), `get_object_ids` = real cell/track ids for `mark_cells`/`mark_tracks` (BIDIR follow-up — replaces blind id-guessing; supports stride-uniform sampling for coverage), `get_cohort_qc` = per-set outliers via `/api/qc/cohort`, `get_repl_api` = the notebook/REPL data-access surface, `get_module_params` = task param specs, `get_available_plots` = board plot types, `get_session_briefing` = chat startup context + the guidance payload, and the two project RESOLVERS — `list_projects` = "my current project", ordered by `lastOpenedAt`, and **`find_object`** = a bare uid/name → the project it lives in, via `GET /api/objects/find`; every other tool needs a `projectUid`, so without it a quoted uid meant `list_images` over every project until one matched) + `poll_observations`/`set_observer_active`/`get_observer_stats` + **11 additive writes** (`append_lab_log` append-only, `create_notebook`/`create_chain`/`add_analysis_board` create-only, `revise_notebook` snapshot-then-overwrite, `set_notebook_description`, `set_labarchives_context` replace-a-cache, `mark_tracks`/`mark_cells`/`point_at_ui`/`mark_freeform` EPHEMERAL-in-memory 5-min-default TTL; `mark_freeform` addresses a captureId only — the earlier `live_viewer` mode was removed because Claude has no way to author viewport-px without asking), each delegating to the client/monitor.
- **Bidir point-out marks (PR #4)**: `api/src/marks_api.jl` — in-memory `_MARKS_BY_PROJECT` bag (per-project Dict, `ReentrantLock`, lazy TTL cleanup on read; no persistence, no delete route) served by `POST /api/viewer/marks/tracks` + `POST /api/viewer/marks/cells` + `GET /api/viewer/marks?projectUid=…`. Each write publishes a `viewer:mark` WS frame (`{type, kind: "track"|"cell", markerId, projectUid, imageUid, valueName, trackIds|labels, focusId?, label?, ttlSeconds, createdAt}`) that `frontend/src/stores/ws.ts::dispatch()` routes into the existing `setTrackHighlight` / `setPickHighlight` setters — SAME shader paint path the TrackSchemeView "Show" button and the correction cockpit's pick outline already drive. Scope is per (imageUid, valueName) because ids are per-vn. MCP-side allow-list entries `POST /api/viewer/marks/{tracks,cells}` — the only new bidir writes; captures (PR #3) keep their write off the observer surface. Follow-up split as PR #4b: label-balloon overlay + gating-module plot subscription to the two bags (`TrackHighlight.label` / `PickHighlight.label` are already-plumbed placeholders).
- **AI notebook generation**: `api/src/notebooks_api.jl` `_pluto_notebook_source(cells)` serialises Julia cell sources into a valid Pluto `.jl` (env-activation cell prepended), backing `POST /api/notebooks/write` (`api_notebooks_write`, create-only + snapshot v1) → the `create_notebook` MCP tool. Reuses the existing registry/snapshot helpers; Claude's code-gen guidance is in `docs/REPL.md`. The write is create-only so the observer stays non-destructive.
- **REPL / notebook data-access surface**: `app/src/ai/repl_api.jl` — the ONE curated `NOTEBOOK_API` allow-list of notebook-safe read accessors + live docstring introspection (`repl_api_reference`). Generates the `docs/REPL.md` API section (`write_repl_doc`), golden-tested so it can't drift from the code. Served via `GET /api/repl/api` → the `get_repl_api` MCP tool. When adding a notebook-facing accessor, add it here (and give it a docstring — the test enforces it).
- **AI engine contract**: `app/src/ai/agent_runner.jl` — `AgentBackend` + four methods every engine implements (`agent_available`, `agent_label`, `agent_capabilities`, `_run_agent_once`) and the engine-independent driver `run_agent_turn` (stale-session self-heal, "asked for a schema, got none" = failure). `ClaudeAgent` is the only engine; `run_observer_turn` is a thin call into it. Kiwi options on `_build_claude_cmd`: `replace_system_prompt`, `json_schema`, `allowed_tools`, `strict_mcp`, `builtin_tools`. Tested with a fake engine in `app/test/suite/observer.jl`. Design: `docs/todo/KIWI_ASSISTANT_PLAN.md` → *The engine seam*.
- **KiwiRef resolver**: `api/src/kiwi_refs.jl` — `kiwi_ref_shape_error` (the shared schema's shape check, pure) and `resolve_kiwi_ref(project_uid, ref)` → `{ok, check, label, error}`, one resolver per kind, each built on the existing reader (`init_object`, the label-props view with `select_cols(["label"])`, `load_pop_map(...; backfill_save = false)`, the plot registry, the landscape cache, `_read_bb_meta`, `_task_from_fun_name`). Route `POST /api/kiwi/refs/resolve`. Tested both ways per kind against `testpr` (`api/test/suite/kiwi_refs.jl`).
- **MCP connections (what Claude can reach)**: `mcp_connections()` (`app/src/ai/agent_runner.jl`) enumerates every server in the user's Claude config → `GET /api/mcp/connections` → the row model `frontend/src/utils/mcpConnections.ts` (tested) → the **Settings → MCP connections** section, which reuses the existing `.svc-row`/`.svc-pill` chrome and `stateInfo` rather than a second indicator. **Two row KINDS, deliberately not comparable**: `machine` (in `~/.claude.json` — real state, real dot) and `account` (managed by the user's claude.ai account, e.g. LabArchives — **undetectable from here**, so never a green/red dot; listed for discovery, dismissable per `settings.hiddenMcpAccounts`). Add a new account connector as a line in `ACCOUNT_CONNECTORS`, not a special case. A third kind, `cli`, leads the list — Claude Code itself (on PATH? logged in?), the precondition for every machine row; its state comes from `observerSetupReason` (`utils/observerSetup.ts`), the SAME helper behind the lab-log panel's install/login band, so the two can't disagree. Division of labour: Settings holds the DURABLE status + the `--mcp-config` fallback command you go to check; the lab-log band is a CONDITIONAL alert that appears only when something is broken and vanishes when it works.
- **LabArchives context sidecar (Julia)**: `app/src/ai/labarchives.jl` — the ONE reader/writer of `settings/labarchives.json` (`la_doc_path`/`read_la_doc`/`write_la_doc!`/`la_gaps`/`la_briefing`), the experiment as the lab's ELN records it. **Cecelia never fetches from LabArchives** — the connector is authenticated in the user's Claude session, so Claude pulls and calls `set_labarchives_context`; this stores and serves it (which is why a session with no ELN access still gets the context, via the briefing). The sidecar is a CACHE of an external system of record, so it is REPLACED on each sync — that is what licenses rewriting it while the lab log stays append-only; a change worth remembering is appended to the log as a dated `[LabArchives]` block instead. `la_gaps` is DERIVED on every read, never stored: it diffs the declared cohort against `attr_value_counts`, and it is the load-bearing part — attribute levels come from the images PRESENT, so a deleted arm leaves no other trace that the comparison was planned. Routes `GET`/`POST /api/observer/labarchives[/set]`. See `docs/ai-assist/LAB-LOG.md` + `docs/todo/LABARCHIVES_SYNC_PLAN.md`.
- **Image attributes across a collection (Julia)**: `attr_value_counts(imgs; included_only=false)` (`app/src/model/set.jl`) — the ONE tabulation of `img.attr` over many images (name → distinct values → count, first-appearance order). Used by `api_plot_attrs` (the compare-by-attribute picker) and `la_gaps`; don't re-loop `im.attr` for a third answer to "which levels exist".
- **Grouping images BY an attribute (Julia)**: `image_attr_groups(imgs, uids, attrs)` (`app/src/model/set.jl`) — uID → the combined value of `attrs` (values joined with `"."`, empty components dropped; an image with no value is ABSENT, so a gap keeps its own uID rather than joining every other gap under one empty label). The companion to `attr_value_counts` (*which levels exist* vs *which image is in which*), and THE join for every cross-image comparison: `POST /api/plot_data` (summary canvas) and `track_plot_groups` (both track plots) read it, so "Treatment.Mouse" cannot mean two things on one board.
- **JSON3 → native (Julia)**: `json_native(x)` (`app/src/helpers.jl`) — the ONE recursive converter to String-keyed `Dict`s/`Vector`s. Parsed JSON bites twice (Symbol keys, and `JSON3.Object isa Dict === false`), so anything reading a request body or a re-read sidecar and then indexing by string goes through this rather than growing another private `_native`.
- **Session briefing / image QC severity**: `app/src/ai/briefing.jl` (`session_briefing`) — the compact chat-startup context (name/count + flagged images + recent lab log), served via `GET /api/observer/briefing` → `get_session_briefing`. Its flagged-images source is `all_qc_docs(img)` in `qc.jl` — the ONE canonical merge of persisted QC sidecars + the computed calibration fallback, shared with the API image payload (`_image_qc_payload`) so the table indicator and the briefing never diverge. Don't re-merge those two elsewhere. Each flagged image carries `included` (+ a project-level `excludedCount`) and each finding its `fun`: an EXCLUDED image is labelled rather than dropped, and a finding names the task that banked it, because a reading session otherwise leads on an image the user already discarded or on a drop-in example's hardcoded threshold. Both are provenance, not filtering — see `docs/ai-assist/OBSERVER.md`.
- **cecelia_mcp/guidance.py**: the ONE place the server says how to use its own tools — `SERVER_INSTRUCTIONS` (short; goes out via `FastMCP(instructions=…)` into every client's system prompt: resolve the project with `list_projects`, then `get_session_briefing`) + `BRIEFING_GUIDANCE` (long; returned as the briefing's `guidance` field: grouping/replicates, boards, chains, cohort QC, how to open). This is what makes "check my current project in cecelia" a sufficient prompt — it replaced a ~900-word paste-in prompt in `frontend/src/lib/chatHandoff.ts`, which is the copy that went stale twice. **A new MCP tool must be named here and nowhere else** (`GuidanceTest` in `mcp/tests/test_server.py` fails otherwise); per-tool detail stays in the tool's own docstring. `app/src/ai/observer_prompt.jl` (`_OBSERVER_RULES`) is NOT a second catalogue — the in-app agent is spawned against this same server, so it receives both constants; that file carries only the watch loop, the cohort-QC pass, the parameter-suggestion rules and the lab-log discipline, and `app/test/suite.jl` asserts the shared catalogue is ABSENT from it. See `docs/ai-assist/OBSERVER.md` → *The hand-off is one line*.
- **cecelia_mcp/client.py**: `CeceliaClient` (stdlib urllib to the Julia API) with `ALLOWED_ROUTES` allow-list — the read-only guarantee. Never opens images/h5ad itself; talks HTTP to :8080 only.
- **Share-in captures — the "look at this" surface (BIDIR PR #3)**: `api/src/captures_api.jl` writes `<proj>/captures/<captureId>/{meta.json,frame.png}` on `POST /api/viewer/capture` (frontend Share button, never MCP), lists newest-first on `GET /api/viewer/captures`, reads one + inlined frame on `GET /api/viewer/capture`. Envelope shape per `docs/todo/BIDIR_CONTEXT_PLAN.md` Part 2: `{captureId, createdAt, surface, address:{projectUid, imageUid?, valueName?, t?, z?, extentUm?, domAnchor?, plotSpec?}, frames:[{png, bytes}], overlay:[{kind, geom, label?}], viewStateSnapshot?, viewerPropsRef?}`. Additive-only, no delete/mutate; corrupt `meta.json` is skipped (captures are decoration on top of a project, never core). MCP tools `get_recent_captures(project_uid, limit)` + `get_capture(project_uid, capture_id)` on the read side — the latter returns TWO content blocks so Claude both SEES the frame (Image block) and reads the address (envelope dict). The write route is deliberately NOT on `ALLOWED_ROUTES` — captures are authored by the user's Share click, never fabricated by Claude. Guidance: "ON WHAT THE USER JUST SHOWED YOU" in `guidance.py::BRIEFING_GUIDANCE`.
- **Push pairing (BIDIR Part 5, `BIDIR_PUSH_PLAN` PR #1)**: `api/src/push_api.jl` reads/writes `<proj>/settings/push_target.json` (`{socketPath, token, sessionLabel?, pairedAt, pairedFromPid?}`) via `GET/POST /api/push/target`. The GET response NEVER carries the token — the token stays on disk for PR #2's Julia writer only. Wired into `CeceliaClient._request` middleware (`mcp/cecelia_mcp/client.py::_maybe_pair`): every MCP tool with a `project_uid` auto-registers this session's `CLAUDE_CODE_MESSAGING_SOCKET` + `CLAUDE_CODE_MESSAGING_TOKEN` env vars on its first call per project, cached in `_paired`. Explicit re-pair via `register_push_target(project_uid, session_label?)` MCP tool (`server.py`). Silent on any failure — a broken pair never breaks a read. Frontend chip in `ViewerPanel.vue` reads GET and shows "paired ✓ / not paired" next to the Share button. `POST /api/push/target` is on `ALLOWED_ROUTES`; the write is recoverable (a bad record self-heals on next auto-pair).
- **Push writer + fallback (BIDIR Part 5, `BIDIR_PUSH_PLAN` PR #2)**: `api/src/push_writer.jl` connects to the paired Claude Code session's inbox socket and sends `{"type":"auth","token":"…"}\n` then `{"type":"user","message":{"role":"user","content":"…"}}\n` (verified against Claude Code v2.1.278 by extracting the runtime example embedded in the binary's `[uds-messaging]` help string). `format_capture_message(project_uid, capture_id, address)` is the ONE wording — a chat-side grep for `"[cecelia] shared capture"` finds every incident, past and future (Decision 5). Fires from `captures_api.jl::api_viewer_capture` after the capture is on disk; the response body carries `push: "sent" | "fallback" | "not_paired"`. Any exception ⇒ silent `:fallback` + stale record cleared (removes `push_target.json` so the chip flips to "not paired" until the next MCP tool call auto-repairs). Frontend `ViewerWindow.vue` reads `push` and either shows the "sent to your Claude session" toast (skips clipboard) or keeps the existing `#1040` clipboard/toast fallback path unchanged.
- **Push chip polish + WS signals (BIDIR Part 5, `BIDIR_PUSH_PLAN` PR #3)**: `api/src/push_api.jl` broadcasts `push_target:changed {projectUid, paired, sessionLabel?}` on pair-write; `push_writer.jl` broadcasts the same frame with `paired: false` on stale-clear, plus `push:sent {projectUid, captureId}` on successful push. `frontend/src/stores/push.ts` is a thin dispatcher (`tick` + `lastEvent`) that `stores/ws.ts` routes both frame types into; `components/ViewerPanel.vue` watches it, refetches `/api/push/target` on `push_target:changed`, and flashes a transient "sent ✓" chip state for 3 s on `push:sent`. **No ACK reader** — Claude Code's `peer_message_status` notices go to the sender's own inbox socket (via `sendPeerReceipt`), and Cecelia binds none as a raw-socket sender, so the notice never arrives. Reading it would require Cecelia to bind an inbox of its own, deliberately out of scope. `guidance.py` gains one paragraph telling Claude to call `get_capture` when a `[cecelia] shared capture cap-…` message arrives (Decision 15).
- **Headless turns never pair**: `observer_mcp_config(...; headless = true)` (`app/src/ai/agent_runner.jl`) sets `CECELIA_OBSERVER_NO_PAIR` for the turns the app spawns itself (`_write_observer_mcp_config(; headless = true)` → `observer-mcp-headless.json`); `_pairing_disabled()` in `mcp/cecelia_mcp/client.py` then skips auto-pair and refuses `register_push_target`. A headless `claude -p` hands its MCP children its own messaging socket, so without it every Ask Claude / Watch pass re-paired the project to a session about to exit. The terminal's `observer-mcp.json` and the `claude mcp add-json` spec stay pairing-enabled.
- **cecelia_mcp/monitor.py**: `SessionMonitor` + `normalize_frame` — pure, thread-safe session-state for the 10-attempts pattern (counts terminal task outcomes per `(image_uid, fn)` off the WS stream) + note/lab-log events, plus the per-session throttle (`surfaceCap` → silent lab-log flush via `drain_for_log`), token-cost estimate (`stats`), and off switch (`set_enabled`). No I/O; unit-tested. `poll` drains observations.
- **cecelia_mcp/wsclient.py**: thin WS listener (`observe`/`start_listener`) feeding the monitor from `ws://…/ws`; best-effort, reconnects, receive-only. Backend events it consumes: `chain:node:*`, `task:status` (now carries `fun`), `image_note_added`, `lab_log_entry_added`.
