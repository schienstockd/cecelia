# Data access (the canonical readers/writers — never hand-roll)

- **Structure anisotropy / fibre orientation (Python)**: `python/cecelia/utils/anisotropy_utils.py` — the local orientation field behind the quiver plot and the per-image `anisotropy` readout. `structure_tensor_field` (production) and `tangent_tensor_field` (the legacy ILEE estimator, kept as a runnable comparison baseline, not an oracle). **Read the direction through `fibre_orientation` / `tangent_orientation` — never index `orientation_eigvec` by hand: the two estimators use OPPOSITE conventions (structure tensor → MINOR eigenvector is the fibre; tangent tensor → MAJOR), and getting it wrong rotates every arrow 90° silently.** Also `weighted_anisotropy` (the length-weighted per-image scalar), `direction_contrast` (the tuning objective — near-vs-far agreement; do NOT tune on coherence or on neighbour agreement alone, both are trivially minimised by blurring), `compare_fields` (one call answering "how does this differ from the old version?"), `pool_by_box`/`box_centres`/`box_lengths`/`acute_angle`. Used by `app/src/tasks/segment/branching_run.py`; see `docs/SEGMENTATION.md` and `docs/todo/SPATIAL_ANISOTROPY_PLAN.md`.
- **Image / OME-ZARR (Python)**: `python/cecelia/utils/zarr_utils.py` — `open_as_zarr`/`open_zarr` (image AND labels; zarr STORES only — sources are converted by the import task first, and a non-store raises rather than falling back to a TIFF reader), `series_base` (structural layout detection), `read_axes`/`read_scale`/`read_multiscales_meta`, writers `create_multiscales`/`create_zarr_from_ndarray`, and `multiscales_metadata` (the shared NGFF `.zattrs` builder used by both the image writer and the label writer). All store access routes through here. **Streaming writers (bounded memory, use these to avoid materialising a whole T×C×Z×Y×X image in RAM):** `open_multiscales_for_writing` (create an empty per-plane-chunked level 0 + metadata up front, then fill it a plane/channel at a time), `write_multiscale_pyramid` (build the downsample pyramid one timepoint at a time — also used internally by `create_multiscales`), `copy_stream` (per-timepoint carry-through copy). Adopted by the drift / AF / cellpose correction tasks and the segmentation label writer.
- **OME-XML (Python)**: `python/cecelia/utils/ome_xml_utils.py` — `load_ome_xml` (cached), `read_pixel_unit`/`read_scale_from_ome_xml`/`read_time_increment`, `read_imagej_metadata`; writers `save_meta_in_zarr`/`write_ome_xml`. The one TIFF/ImageJ metadata reader.
- **Imaris `.ims` source metadata (Python)**: `python/cecelia/utils/ims_meta.py` — `time_increment(path)` recovers the frame interval Bio-Formats never exposes. `ImarisHDFReader` reports `TimeIncrement = null` and `PlaneCount = 0` (so no `DeltaT` either) and puts the timing in the unstructured original-metadata table instead — the dump ImageJ prints under "Show Info", which is why ImageJ appears to know the interval and we did not. Three sources, best first: `DataSetTimes/Time` `Birth` (nanoseconds, exact) → `DataSetInfo/TimeInfo/TimePointN` wall-clock stamps → `DataSetInfo/OIR Dataset Size/Time Step` (Olympus-only and NOMINAL, flagged as such). **A measured series that isn't uniform yields NOTHING, not its median** (`summarise_gaps`, `UNIFORM_TOL`) — a paused acquisition has no single interval, and a plausible number here is indistinguishable downstream from a real one. Reached from Julia via `app/src/tasks/importImages/read_ims_time_interval_run.py`, called by `_recover_ims_time_increment!` (`omezarr.jl`) from BOTH the import task and `resync_ome_meta!`, so images imported before this existed are repaired by Refresh metadata rather than a re-import. The Imaris counterpart of `read_imagej_physical_size_run.py`. See also `ims_relink.py` (the `ims-softlink` data patch).
- **Cell data `.h5ad` (Python)**: `python/cecelia/utils/label_props_utils.py` — `LabelPropsView` chain (read `view_cols`/`view_centroid_cols`/`filter_by_label`/`as_df`/`obsm`; write `add_obs`/`add_categorical_obs`/`add_obsm`/`save`). The one Python existing-file h5ad open path. Only NEW-file *creation* uses `anndata` directly (measure/tracking output).
- **Store layout (Python + Julia, one decision)**: chunk keys are **always NESTED**, in both zarr formats — `CHUNK_SEPARATOR_DEFAULT` (`python/cecelia/utils/zarr_utils.py`) and `STORE_LAYOUT_CHOICES`/`CHUNK_SEPARATOR_DEFAULT` (`app/src/config.jl`), with `bf2raw_format_flags` never emitting `--no-nested`. The `flat` option was **removed** 2026-08-14: it saved ~5% on a real 3.5 GB movie (not the ~14% its 81 MB fixture suggested) at identical read time, and produced a store conforming to **no published NGFF version** — nested storage is what NGFF 0.2 introduced, so flat keys are 0.1 storage under the 0.4-shaped metadata written beside them, which is why bioformats2raw stamped `0.1` on `--no-nested` imports while our own writers stamped `0.4` for the identical layout. The separator is therefore **not inherited** by derived stores (`store_encoding_of` inherits the zarr FORMAT only, per D9), so a correction of a legacy flat image comes out nested. Reading flat stores is unaffected — the separator is self-describing (v2 `.zarray` `dimension_separator`, v3 `chunk_key_encoding`). Rationale + measurements: `docs/todo/ZARR_V3_PLAN.md`.
- **Store compression (Python + Julia, one decision)**: `python/cecelia/utils/zarr_utils.py` — `store_compressor(kind)` is the ONE place the codec of anything we write is decided (`kind='image'` → `blosc/zstd-3` + byte shuffle; `kind='labels'` → plain zstd, the opposite answer because label planes are >99% zero and blosc's blocking breaks the runs). **Every `create_array`/write-mode `open_array` must pass it** — enforced by `python/cecelia/tests/test_store_compressor_convention.py`, which also bans constructing a codec anywhere else. Measured numbers live on the constants. User-selectable via `[zarr].imageCompressor` (Settings → Storage, `/api/storage/compressor`); the choice reaches Python through the `CECELIA_IMAGE_COMPRESSOR` env var `run_py` sets. Julia carries a mirrored table (`app/src/config.jl` → `IMAGE_COMPRESSOR_CHOICES`, `bf2raw_compression_flags`) because bioformats2raw takes CLI flags; the two are pinned equal by a suite test. Existing stores are re-landed by `rechunk_zarr.py`. Why bit-depth reduction is NOT the answer instead: `docs/FUTURE.md`.
- **Staged store writes (Python)**: `python/cecelia/utils/zarr_utils.py` — `staged_store(final_path)` (context manager: yields a `{name}.partial` sibling, renames it into place on clean exit) + `promote_store`. The ONE way to write a store — every image-version and label writer goes through it, so a cancelled run can't leave `ccid.json` advertising a truncated store (on a single-level store the missing frames read as silent zeros). The store-level twin of `write_atomic`. Suffix constants mirrored in Julia as `STORE_STAGING_SUFFIX`/`STORE_SUPERSEDED_SUFFIX` + `staging_store_path` (`app/src/utils.jl`) for the live preview and the sweep; pinned in step by a test. Enforced by `python/cecelia/tests/test_store_staging_convention.py`. Broom for debris a killed run leaves: `python/cecelia/utils/store_sweep.py` (the `store-debris` data patch) — detects STRUCTURALLY (unregistered stores, `.zattrs`-declared-but-absent pyramid levels, import scratch) as well as by suffix, because import writes straight to the final name and a name list only covers writers someone remembered; `summarise()` feeds the Settings storage box so the same detector reports the bytes it would free.
- **Moving an array block between our Python processes (Python)**: `python/cecelia/utils/block_transfer.py` — `encode_block`/`decode_block` (zlib+base64 over the JSON WS protocol, dtype carries byte order) + `place_block_lazy` (a block dropped into a LAZY dask array of the full extent, so a layer can be full-image-shaped without allocating the image; T/Z chunked to 1 or one plane materialises the volume). The ONE codec, used by both ends — `preview/preview_worker.py` encodes, `napari_bridge.show_task_preview` decodes, and Julia (`preview_show_command`) is a pass-through that never decodes. Use this instead of writing a throwaway store for something that only needs to be looked at; the task preview did the latter first and it cost a whole staging/sweep lifecycle. **WS frame cap — ONE number, all four ends:** `Cecelia.WS_MAX_FRAME_SIZE` (`app/src/utils.jl`, passed as `maxframesize` on both Julia clients) = `WS_MAX_SIZE` in `napari_bridge.py` and `preview_worker.py`; pinned equal by the `resident python legs agree on their frame cap` testset. Both defaults are too small for a realistic payload and neither degrades gracefully — the receiver closes the connection (`1009: message too large`), so it fails on big images only. Producers still bound themselves: `FLOW_INSPECT_MAX_PX` (`api/src/optical_flow_api.jl`) + `frontend/src/utils/flowRegion.ts` crop the flow sheet rather than leaning on the cap.
- **Registering a task's output (Julia)**: `commit_state!(img) do raw … end` (`app/src/model/project.jl`) — THE way a task writes its result into `ccid.json`. Does the read-modify-write inside the image's transaction, so two tasks finishing on one image can't lose each other's registration (each write is individually intact — the loser is built on stale data, which atomicity alone does not fix). Locks the COMMIT, never the computation: run the long work first, then commit. `with_transaction(f, obj)` is the bare form (in-process `ReentrantLock` + cross-process lockfile, reentrant, abandoned-lock reclaim). Segmentation backends get it via `register_label_files!` (`app/src/segmentation.jl`) — don't hand-roll a labels-dict write. Do NOT re-read/poke/write a state file outside this.
- **Which segmentation to act on (Julia)**: `resolve_value_name(img[, value_name])` (`app/src/model/image.jl`) — the caller's `value_name` when given, else the image's **active** one. The `defaultOnly` half of R's `cciaImage` `valueNames`; `img_value_names(img)` is the list half. Nine sites used to inline `something(value_name, get(img.label_props, "_active", "default"))`, hardcoding the key and the fallback that `VERSIONED_ACTIVE_KEY`/`VERSIONED_DEFAULT_VAL` name. `label_props`-only on purpose: `labels`/`branch_labels` are `Dict{String,Vector{String}}` and cannot hold an active marker — branch names come from `img_branch_value_names` (disk) instead.
- **What a task WRITES, and under what name**: `frontend/src/utils/taskOutput.ts` — `taskOutput(def, params)` → `{name, namespace}` or `null`. THE resolver, because **eleven task params across six key spellings** name an output (`outputValueName`, `valueNameSuffix`, `graphSuffix`, `statsSuffix`, `colName`, `modelName`) and the keys are NOT synonyms — each names a different storage shape (versioned-dict key / column suffix / filename stem / obs column / global vault file), so one shared key would make the handlers lie. A task spec declares `namespace` instead; that declaration is also what makes the concept **greppable**, which a key name never was (two scoped searches during the design concluded "3 tasks" and "12 tasks", both wrong). Three callers, one rule: the suggestion list (`ParamRenderer`), chain edge propagation (`ChainModule.nodeOutputValueName`) and the napari preview layer stem (`taskPreview.previewValueName` — which keeps its OWN input-version fallback, the layer's question, not the output's). `consumerField(ns)` narrows to the field a consuming `valueNameSelection` can read and returns **null** where none can (a cluster suffix is not an image version — the old `normField` collapsed those to `filepath`). `normaliseField` collapses the singular/plural trap already on disk: consumers say `field: "filepaths"`, a fixed output says `outputField: "filepath"`, and compared raw they never match. Widget: `SuggestInput` below. The namespace's SCOPE is not uniform — per image, per (image, value_name) for `clusters`/`regions`, and GLOBAL for `models` (the vault, whose suggestions ride injected spec options rather than the image payload). Image-owned accessors: `img_stats_suffixes`, `img_cluster_suffixes` (a wrapper over `_clustfeatures_suffixes`, which stays in `gating/population_manager.jl` because it owns the sidecar's three historical layouts), `flow_model_names` (over `list_coastal_models`). Params are also remembered PER NAME — `meta["funParamsByName"]`, resolved server-side by `Cecelia.task_output_name`, the Julia twin of `taskOutput` pinned against the same specs. Plan + the locked decisions: `docs/todo/VALUE_NAME_INPUT_PLAN.md`.
- **Type freely, with what you already use offered (Vue)**: `frontend/src/components/SuggestInput.vue` (+ pure `utils/suggestInput.ts`, tested) — the ONE control for a field whose value is user-invented but usually a REPEAT. Callers: task params (`valueNameInput`), Metadata → *Assign value* (attribute values — the grouping axis, where a typo invents a cohort group rather than erroring), Movies row tags (`separator=","`, completing the token at the caret), and the recorder's "name" suffix on all three movie surfaces (fed by `composables/useMovieSuffixes.ts`, which caches ONE `/api/movies` fetch per project — the suffix is registry-banked by `register_movie!`, never parsed back out of a filename). A strict `<select>` is the twin, right where the value must already exist. **Not for a UNIQUE-name field** (populations, notebooks, model renames all reject duplicates — offering them suggests a guaranteed failure). **Not a native `<datalist>`**: that popup is browser chrome, ~16px against a `0.82rem` input, unreachable by any selector. Built on `TeleportPopover`; binds `$attrs` LAST and uses `stopImmediatePropagation` so accepting with Enter does not also fire a caller's `@keydown.enter`/`@keyup.enter`. See `docs/UI.md` → *Suggesting what you already use*.
- **Durable writes (Python)**: `python/cecelia/utils/atomic_io.py` — `write_h5ad_atomic` / `write_json_atomic` / `write_atomic` / `atomic_path`. THE way to write anything that must survive a kill: temp sibling + `os.replace`. `task:cancel` kills the Python process by design, so an in-place write could leave a truncated `.h5ad` (the cell table — no partial readability, no previous content). Covers every `write_h5ad` (creating or rewriting) plus the durable `spatialStats` sidecar. Temp names are suffixed AFTER the extension so a leftover can't match a discovery glob. Enforced by the `no_bare_write_h5ad` detector. Julia counterpart: `write_atomic` below; store-level counterpart: `zarr_utils.staged_store` (a directory can't be `os.replace`d over another, so it's deliberately a separate helper).
- **Object state files (Julia)**: `app/src/utils.jl` `write_atomic` / `write_json_atomic` — the ONE writer for every durable state file (`ccid.json`, `project.json`, the gating/QC/spatial/board sidecars, chain templates + `run.json`, `custom.toml`, the lab log, Pluto notebooks). Writes tmp-then-rename, so a kill mid-write leaves the PREVIOUS content instead of a truncated file — a truncated `ccid.json` used to fail the whole project load. Read side: `read_state_json` / `read_ccid_raw` (`app/src/helpers.jl`), which name the file when it won't parse. Locate the file with `state_file(obj | meta_dir | proj_dir, uid)` (`app/src/model/image.jl`) — never join `"ccid.json"` or the `1/` segment yourself. Enforced by the `no hand-rolled state writes` testset.
- **Board SPEC expander (Julia)**: `app/src/analysis_board_spec.jl` — the ONE validator/expander turning a semantic board spec (which plots, which populations, what it compares) into a `LayoutEntry`, behind `POST /api/boards/add` → the `add_analysis_board` MCP tool. Everything it enforces exists because a bad board renders BLANK with no error: `popType` is derived and an explicit one must *reach* the named populations (`plot_pop_types` + `board_spec_populations` — the picker's own enumeration); `compare_by` writes the board-level `shared.compareMode`/`compareAttr` and validates attribute names against the project's images; `board_display_name` decodes HTML entities so a name renders as written. `pops` and `attrs` are injectable so every accept/reject rule is testable without a project on disk. Don't add a second path that writes a board — `/api/projects/boards` is the browser's whole-document autosave, deliberately not allow-listed. See `docs/ANALYSIS.md`.
- **Analysis boards document (Julia)**: `app/src/analysis_boards.jl` — the ONE reader/writer of `settings/analysisBoards.json` (`boards_doc_path` / `normalise_boards` / `read_boards_doc` / `write_boards_doc` / `boards_doc_payload`). Reads BOTH historical shapes (the tab array flat at `tabs`, and the legacy `TabGroup` nested at `tabs.tabs`), writes only the flat one, and owns the `version` optimistic-concurrency counter. Three callers in two layers use it — the autosave route + the project-open payload (`api/src/routes.jl`) and `board_summaries` (`ai/lineage.jl`). Don't parse this file anywhere else: the last time it had two parsers they disagreed about its shape and `get_analysis_lineage` reported no boards on every project that had them, silently. `BoardsDoc.present`/`.readable` deliberately distinguish "no file" from "a file I can't read". See `docs/ANALYSIS.md`.
- **Pixel→µm centroid conversion**: `scale_centroids!` (`app/src/label_props.jl`) / `scale_centroids` (`python/cecelia/utils/label_props_utils.py`) — THE one conversion, per axis BY NAME (2D-safe), reached from `pop_df(…; centroids = :physical)`. Used by `track_measures`, `cellContacts`, `detectAggregates`, `spatial_utils`, btrack. Never re-derive `[sz,sy,sx] × centroid`: five copies of it is how tracking ran in pixels while its own measures reported µm/min (#491). Centroids on disk are ALWAYS pixels and `centroid_t` is ALWAYS a frame index (`docs/DATAMODEL.md`); `img_is_calibrated` tells "uncalibrated" from "calibrated at 1.0".
- **Cell data `.h5ad` (Julia)**: `app/src/label_props.jl` — the sole Julia HDF5 chokepoint: `label_props(...) |> select_cols/filter_rows |> as_df` read chain, `add_obs |> save!` write path, `_with_h5` lock. **`uns` (whole-file metadata, not per-row)**: `uns_keys` / `uns_array` / `uns_dict` / `uns_df` — one reader per AnnData encoding (array, dict-group, dataframe-group). `uns_array` returns the PRODUCER's (numpy) dimension order: HDF5 is C-order and Julia is column-major, so a numpy `(T,y,x,comp)` array arrives with EVERY axis reversed — including equal-length axes, which swap silently. Categorical/string obs writes delegate to Python via `run_py` (`write_categorical_obs`).
- **Categorical/string obs (Python)**: `python/cecelia/utils/obs_utils.py` — `write_categorical_obs`, a thin driver over `LabelPropsView.add_categorical_obs` (the categorical-encoding half of the h5ad write contract; Julia writes only numeric obs).
- **GPU device (Python)**: `python/cecelia/utils/gpu_utils.py` — `torch_device()` → `(use_gpu, device)`, the one CUDA→MPS→CPU detector for torch-backed tasks (cellpose segment + denoise).
- **Population membership (Python)**: `python/cecelia/cecelia_client.py` — `CeceliaClient` (stdlib HTTP to the Julia gating API); `python/cecelia/utils/pop_utils.py` `PopUtils.pop_df` is the Python population accessor.
