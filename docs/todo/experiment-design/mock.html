Experiment design — the user's path

Target UX for docs/todo/EXPERIMENT_DESIGN_PLAN.md. A static mock: no behaviour, and plot values are illustrative, not measured. The worked example is the T cell set (intravital, images first). Frame 2b shows the same dialog for a PhenoCycler set started design-first, because the design is not specific to one technology. Nothing here blocks: every reservation is a warning. Read from the real set: the names, runs, folders, panels, the mice per day and the confound with day. Illustrative: the plot values, tracking parameters, calibration, statuses and the design-history entries.

1 · Files registered, before import → the question and the mode
A new set is empty, so nothing opens then. The dialog opens once files are registered into a set with no design: names and original paths exist, and nothing has been converted yet. The question comes first, because everything after it is judged against it. Exploratory is one click and explicit. It is a choice the record keeps, not a skipped step.

2 · Layout: suggested from names and original folders
The files are registered but not imported. Cecelia suggests a design from the attributes, the file names and the original paths, using the Metadata panel's extraction rules, so the user can see and edit each rule. Every suggested value is inferred until confirmed. The run suffix sits beside the name, so a name the user forgot to change can be caught here.

3 · Confirm: the grid and what it can support
The user signs off on the actual grid, not a description of it. Reservations appear here, before any processing, and each one says what it threatens for the question. Confirming records the design as “inferred, then confirmed”. Nothing is blocked.
