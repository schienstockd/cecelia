# GUI clarity audit, P0 step 4: density, cut and merge candidates

Worktree `cecelia-gui-clarity-audit-archive`, read 2026-11-10. Paths are relative to `frontend/src/` unless noted.
Screenshots: `shots/run3/<state>/<route>.png` in this scratchpad (1440x900, first paint). Builds on
`p1_census.md`, `p2_journeys.md` and `p5_consistency.md`. Where one of those already found something,
this file only cites it (for example "p2 4.1") and adds the cut or merge decision.

**Usage is unknown everywhere.** There is no UI telemetry. "Who would miss it" names the role and the
scenario from code and docs, not measured use. An item is called rarely used only when code or docs give
evidence for it (Coming soon, an off-by-default toggle, a duplicate of the same settings key).

**Effort:** S = one file and under ~30 lines. M = 2–5 files or a small new piece (a menu or slot). L = a
cross-page or design change that needs a maintainer call.

**Ground rules respected:** Cecelia works fully without Claude, so no non-AI path depends on an AI
surface. Replacements reuse canonical pieces (`TeleportPopover`, `CollapsibleSection`, `ChipSelect`,
`.cc-btn*`, `ComingSoonBadge`, the maturity tiers). Claim review stays on plots.
