# Remote access — token-authenticated direct browser access

**Status:** planning (2026-08-27)

## Goal

Let a user spin up a Cecelia VM, click a shareable link, and reach the app in a browser —
**no SSH tunnel, no third-party service, no HTTPS setup**. The product line is "spin up a VM, click
the link"; today that requires an SSH tunnel because the HTTP/WS server has no auth
(`api/src/server.jl:637-643`), which reduces Cecelia's reach for the immunology users it's for.

The workaround-until (SSH tunnel) is documented at `docs/INSTALL.md` → *Running on a remote server*.
This plan replaces it with the durable answer.

## Non-goals

- **No HTTPS.** The load-bearing reason is that Cecelia ships in-box — every alternative that gives
  real HTTPS costs a subscription (Cloudflare, Tailscale), a domain, or a Let's Encrypt setup we
  can't wire into `install.sh` without asking the user to buy something or configure DNS. Users who
  need HTTPS put Caddy in front — one-paragraph doc pointer, no code. TLS overhead on the
  image-viewer slab path (see [`WEB_VIEWER_PLAN.md`](WEB_VIEWER_PLAN.md)) is a **secondary and
  unmeasured** consideration; don't lean on it as the argument. **Accepted risk (see Risks
  below): the token — and the session cookie — travel in the clear.**
- **No third-party auth.** No Google IAP, Tailscale, Cloudflare Access. Cecelia stays self-contained.
- **No multi-user identity.** One token per install; anyone with the token is "the user". Cecelia's
  data model is already single-tenant; this plan doesn't reshape that.
- **No token rotation on a timer.** Would break shareable bookmarks. Rotation is a manual CLI action.

## Prior art in the codebase

- `api/src/repl_api.jl` (`_host_is_loopback` at line 24) — the debug console's hard-gate against a
  non-loopback bind. **The token guard follows the same shape**: a small predicate at the top of the
  request path, tested against `_BOUND_HOST[]`. Do not build a bespoke variant.
- `api/src/server.jl:640` — `CECELIA_HOST` env override. Kept unchanged; the plan adds the token
  layer *on top* of the existing bind logic.

### Verified before designing

- **Sole HTTP entrypoint on :8080 is `handle_stream`** (`api/src/server.jl:711` binds it via
  `HTTP.listen`). Grepped every `HTTP.listen*` / `HTTP.serve*` / `WebSockets.serve*` across
  `api/src/` and `app/src/`; the only other server is `app/src/runner/server.jl:430` (dev-only task
  runner on port 7657, hard-coded to `127.0.0.1`, out of scope). Static/binary/WS paths inside
  `handle_stream` all sit *inside* the same function, so one guard at the top covers them.
- **Client-address lookup is `Sockets.getpeername(stream::HTTP.Stream)`** — HTTP.jl exposes it in
  `HTTP/src/Streams.jl:47` (returns `(ip::IPAddr, port::UInt16)`), keyed off the underlying TCP
  socket, not a spoofable `X-Forwarded-For`. Loopback bypass compares `ip` against
  `Sockets.IPv4("127.0.0.1")` / `Sockets.IPv6("::1")`.

## Decisions (2026-08-27)

1. **Model: Jupyter's `?token=` pattern.** First visit is
   `http://<vm>:8080/?t=<token>`; server accepts the token, sets a cookie, and the frontend does
   `history.replaceState` to drop the query so the token doesn't linger in the URL bar, history, or
   any referer.

2. **Token storage: `~/.cecelia/custom.toml → [server].access_token`.** 32 bytes hex generated by
   Julia's stdlib `Random` at first server start if absent. **Overridable by `CECELIA_TOKEN` env**
   for CI / scripted use. Never rotates automatically; rotation is a CLI action.

3. **Chokepoint: one guard at the top of `handle_stream` in `api/src/server.jl:573`.** Covers the
   four static-bypass paths (`/api/board-assets`, `/api/movies/file`, `/api/viewer/slab`, static
   frontend), the API router, AND the WS upgrade — the guard runs *before* the branches. This is why
   we don't scatter checks into each handler.

4. **Loopback bypass.** Skip the token check when the client address is `127.0.0.1` / `::1`. Keeps
   dev flow unchanged, keeps the pattern consistent with the existing REPL loopback gate. Detected
   via `Sockets.getpeername(::HTTP.Stream)` (see *Verified before designing*), not a spoofable header.

5. **Default bind stays `127.0.0.1`.** Laptop installs need zero new setup and are unaffected. The
   VM install path sets `CECELIA_HOST=0.0.0.0` (via `install.sh` when a VM-scope flag is passed —
   see Phase 3). **The server refuses to start on a non-loopback bind if no token is configured** —
   a fail-closed guard so an operator can't accidentally publish an auth-less server.

6. **REPL guard interaction.** `_host_is_loopback` in `repl_api.jl` is unchanged. On a `0.0.0.0`
   bind the debug console remains disabled — exactly as today. The token doesn't unlock the REPL;
   that's a separate, deliberately harder-to-reach surface.

7. **Cookie: `HttpOnly; SameSite=Strict; Path=/; Max-Age=31536000`.** Not `Secure` (we're HTTP; the
   `Secure` flag would refuse to send the cookie and break the whole flow). `HttpOnly` blocks JS
   access — token exchange happens before the frontend needs it, and all subsequent auth is by
   cookie.

8. **CLI helpers.**
   - `pixi run token` → prints the current `http://<host>:<port>/?t=<token>` URL for an existing install.
   - `pixi run token --rotate` → generates a new token, writes it, and prints the new URL. Documented
     to invalidate existing bookmarks and log every browser session out.

9. **Frontend swap-in.** On first load, JS reads `?t=` from `location.search`, POSTs it to
   `/api/session/exchange`, gets a 204 + `Set-Cookie`, calls `history.replaceState` to strip the
   query, then normal fetches / WS work by cookie. If exchange fails (bad or missing token), the
   server serves a plain `/token` HTML page with a paste box that hits the same exchange endpoint.

10. **CORS unchanged for now** (`Access-Control-Allow-Origin: *` in `server.jl:628`). Cecelia's
    frontend is same-origin with the API, so the wildcard only matters for cross-origin embedders —
    which don't exist yet. Revisit if a use case appears.

## Phases

Each phase is independently shippable.

- **P1 — server-side token.** Adds `[server].access_token` to `custom.toml`, generator on first
  start, middleware in `handle_stream`, `/api/session/exchange` endpoint, loopback bypass, refuse-
  to-start-without-token guard on non-loopback binds. Julia tests in `api/test/` — **the
  fail-closed guard ships with its own test in the same commit**; it is the load-bearing security
  property and lands verified, not on faith. No frontend change — `curl -H "Authorization: Bearer …"`
  works. Ships behind an operator-set `CECELIA_HOST=0.0.0.0`; loopback installs see zero behaviour
  change.

- **P2 — frontend URL→cookie handoff.** ~30 LOC in the app shell: read `?t=`, exchange, replaceState.
  Small `/token` HTML fallback for a paste flow (rendered from Julia; not a Vue route so a token-less
  visitor never touches the SPA). Vitest for the exchange helper.

- **P3 — installer wiring.** `install.sh` accepts `CECELIA_SERVER_MODE=vm` (or similar; name TBD).
  Sets `CECELIA_HOST=0.0.0.0` in the launcher, generates the token, prints the shareable URL at the
  end of install. Rewrites `docs/INSTALL.md` → *Running on a remote server* to replace the SSH-tunnel
  section with the direct-URL flow; the tunnel path becomes a one-paragraph "Advanced: HTTPS via
  reverse proxy" pointer.

- **P4 — CLI polish.** `pixi run token`, `pixi run token --rotate`. Doc note on what rotation
  invalidates.

## Test plan

Julia (`api/test/`):
- Request with valid token in Authorization header → 200.
- Request with valid token in `?t=` query → 200 + `Set-Cookie`.
- Request with valid cookie → 200.
- Request with none / bad token → 401.
- Loopback request without token → 200 (bypass).
- WS upgrade without token → 401 before upgrade.
- Server refuses to start when `HOST != 127.0.0.1` and `access_token` is empty.
- REPL loopback guard still refuses when bound `0.0.0.0` even with a valid token.

Frontend (Vitest): URL exchange helper → cookie set → `replaceState` fires exactly once.

Manual (VM): fresh install, browse to `http://<ip>:8080/?t=<token>` from a laptop, run a pipeline
end-to-end, confirm `nvidia-smi` shows GPU use.

## Risks / open questions

- **Plaintext token + cookie on the wire (accepted).** HTTP means the token in the URL query on the
  first hit and the session cookie on every subsequent request travel in cleartext. Anyone with a
  packet-capture position between the laptop and the VM — same LAN, an intermediary router, a noisy
  co-tenant VM sharing switching fabric — can lift either. This is the price of "no subscription,
  no cert management" and is the reason HTTPS is a *non-goal we can document a fix for*, not a
  *problem we deny exists*. Users on untrusted networks should Caddy-terminate.
- **Token in URL leaks to server logs.** HTTP.jl's `@info` on requests must redact `?t=` before it
  hits `[server:log]`. One-line filter in the log builder.
- **Token in URL leaks to referer.** First hit is same-origin; only leaks if the frontend triggers a
  cross-origin fetch before `replaceState` completes. Exchange-then-replaceState happens in the app
  shell before any Vue route mounts — verify with a test that no external fetch fires from the app
  shell.
- **Cookie survives refresh; token in URL doesn't need to.** After the first exchange, refreshes and
  reopens use the cookie. If the cookie is cleared, the user re-visits the `?t=` URL.
- **Firewall rule.** Users must open TCP 8080 on the cloud firewall. The installer output prints the
  exact `gcloud compute firewall-rules create …` line; doc has the equivalent for AWS/Azure.
- **Concurrent sessions.** Cookie is per-browser; multiple laptops can share the same token. Fine
  for single-user.
- **HTTPS door.** If users ask for it, Caddy sidecar + Let's Encrypt is the intended path — no
  Cecelia code change needed, only a doc section. See Non-goals.
- **CECELIA_SERVER_MODE=vm naming.** Bikeshed. Could be `CECELIA_BIND=public`, `CECELIA_REMOTE=1`,
  or piggyback on the existing `CECELIA_INSTALL_SCOPE`. Deferred to P3.
