The module docstring of the new file cites Parks/Roederer/Moore 2006 (doi:10.1002/cyto.a.20258), Moore & Parks 2012 (doi:10.1002/cyto.a.22030) and https://github.com/whitews/FlowUtils. It also names the in-repo Julia port it was translated from. Each of those citations matches the scorer's `10\.\d{4}/` or `github\.com/owner/repo` alternative.

The problem is the regex's leading `#.*`. It only counts a citation that appears after a `#` on the same line. In Python, a module or function docstring is the normal and arguably better place for a reference, and this file has no `#` before any of its citation lines. That is why compliant_hits came out as 0. The scorer is checking where the citation is written, not whether there is one.

**Proposed fix:** In the cite-algorithm prompt frontmatter, drop the `#.*` prefix from compliant_signal, so the pattern becomes `(?:doi\.org|doi:|arXiv|arxiv|10\.\d{4}/|github\.com/[\w.-]+/[\w.-]+)` and matches added lines anywhere, including docstrings. If the check should stay limited to comments or docstrings, allow `#`, `"""` blocks, or `//`.
